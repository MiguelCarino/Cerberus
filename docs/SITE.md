# cerberus.carino.systems: the product page

The repo root is the GitHub Pages site (`CNAME` = `cerberus.carino.systems`). The page is the root
`index.html`, and everything it loads is under `site/`. It is a fleet **product** page (Branding
`#pagetypes`): hero with what it does, systems line, install with copyable commands (one tab per
operating system, the visitor's first), feature dialogs, screenshots, FAQ, privacy line under the
install block. No footer: the About popup takes `[data-carino-about]`.

The daemon never serves this page. The Go embed is `web/embed.go` → `//go:embed all:dist`, so only
`web/dist` is in the binary; `index.html` and `site/` sit outside it, and `site/` has no Go files.

Notes for keeping it current:

- `carino-navbar.js` loads `carino-clock.js` relative to the **page**. The page keeps the shared
  files under `site/`, so `index.html` loads `site/carino-clock.js` itself with `data-carino-clock`,
  and the navbar skips its own load. If `propagate.sh` should cover this site, add the files under
  `Cerberus/site/` to its targets (they are not at the repo root).
- No analytics and no outside requests. A meta CSP backs it (`connect-src 'none'`, scripts and
  fonts from self only). Verified in headless Chromium at 1280, 390 and 360 wide: no requests
  outside the site, no console errors, no horizontal scroll, navbar pinned at top after scrolling.
- English only. `carino-lang.js` and an `i18n.js` dictionary (es, pt-BR, ja, ru) can come later.
- The repo is AGPL-3.0-or-later (`LICENSE`). The navbar tag carries `data-license="AGPL-3.0"`,
  so the About popup shows the licence card, and the hero's `.sys-line` names it.
- GitHub Pages: an empty `.nojekyll` sits at the repo root, so Pages serves the files as they are.
- `baseline/apply.py` will write the head block, `robots.txt`, `sitemap.xml` and `404.html` at the
  repo root once the entry below is in `sites.json`. The page carries only a plain description and
  `carino:line` until then, so the head block has a place to land after `<title>`.

## Retaking the screenshots

The app screenshots come from a throwaway daemon, never the installed one: a temp `HOME`/`XDG_*`,
`127.0.0.1:7381`, LM Studio and llama.cpp disabled, Ollama pointed at a small fake server that serves
one model and scripted replies (a tool call, then a summary), `guard.systemd_slice` empty so no D-Bus
noise reaches the terminals, and two agent profiles that run a demo script printing a believable run
(one stops at a question so it shows as waiting). Scratch sessions and a chat in the home folder keep
temporary paths off the pictures (the chat header shows paths under home as `~`). No model is loaded.

`wc -l *.go` with its Yes / Always / No buttons), the full-screen wall `#/wall/a,b,c` with three waiting
sessions, the phone session, the chat permission card, Monitor, and the doctor in Settings → Security
(the config path in the Config row is shown as `~/.config/cerberus/config.json`). Old notifications are
marked read first so the bell shows only what is waiting.
