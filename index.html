Your own LLMs and coding agents,
steered from your phone.

Carino Cerberus is one small self-hosted service: it runs local models, serves one OpenAI-compatible gateway, and runs coding agents in their own git worktrees.

  • An agent is halfway through a task when you leave your desk? Answer its question, read the diff and accept it from your phone.
  • Several apps each want their own model server? Point them all at one /v1 endpoint, local or cloud.
  • Wondering what a model really costs you? Every request shows tokens, money and watts.

Pre-release · Linux first · builds for macOS and Windows · one static Go binary · AGPL-3.0

01 · Three parts, one service

Three heads, as the name says.

Each part works on its own, and together they let an agent run on a model your own machine hosts.

1

Models

Cerberus runs local LLMs through the engines you already have: llama.cpp (llama-server), LM Studio and Ollama. It never ships an inference engine of its own.

  • Loads a model on the first request and unloads it when it goes idle.
  • Makes room in VRAM before a load, so two models never fight over the card.
  • Records time to first token, tokens per second and energy for every request.
2

Gateway

One OpenAI-compatible endpoint, /v1, for every app on the machine. Each request goes to a local model or to a cloud provider you reach with your own API key.

  • Local models by their own ID, cloud models as provider/model.
  • Keys live in a vault (the desktop keyring, or an encrypted file).
  • Prices, budgets and spend per model, session and day.
3

Agents

Coding-agent sessions run in a repo's detached git worktree behind a test gate, in a folder of yours, or in a scratch folder. Leave them running and steer them from any browser.

  • The built-in agent works with any model the gateway serves; other CLI agents are optional profiles.
  • Live terminal, approvals, diff review, then accept or discard.
  • Accept fast-forwards main. Cerberus never creates branches.
02 · LLM chat

A chat that can do things, and asks first.

The desktop LLM chat, in any browser. It talks to any model the gateway serves, local or cloud, and keeps running when you close the tab.

  • Tools on your machine. The model can read files, search and run commands in the folder you pick. Anything that changes something shows a card first: allow once, allow for this session, or deny with a note.
  • Four modes. Ask me, Auto (read-only commands run on their own), Accept edits, and Plan.
  • Pick up where you were. Recent chats with search; chats from the desktop app open read-only or continue here. ?? gives a quick one-line answer.
  • A mascot, if you like. Eleven of them, drawn in text, reacting to what the model does. Try them here: this is the code the app runs.

04 · Also in the box

The small things that make it work from a phone.

Drop files

Drop, paste or pick files (the camera too, on a phone) and they land in the agent's inbox/. Other Carino pages can hand files over.

One bell

Finished, failed and waiting sessions land in the bell, and on your phone through ntfy or the desktop notifier.

Replay

Each agent run is recorded. Scrub back through the terminal to see what it did and when.

Get models

Pull from LM Studio, Ollama or a Hugging Face GGUF link, with resume, checksums and a disk check. Downloading never loads a model.

Agents start agents

An agent can start child sessions through MCP, within the limits you set, and you approve the tree.

Install as an app

Over HTTPS (your tailnet, for example) the UI installs on a phone home screen and opens offline.

Every option explained

Settings shows each option with its help, checks it before saving and says when a restart is needed. cerberus config does the same in a terminal.

A leaderboard

Which session, agent, model or repo spent the most tokens, money, energy or time this week.

05 · Energy

All the energy goes to the models.

The control plane is built to stay out of the way, and it tells you what the work costs.

  • Quiet when idle. Measured: about 18 MB of memory and 0.01 s of CPU a minute with nothing running, and nothing more with a browser tab open. The page stops its streams and timers when you switch away. Nothing runs a browser engine in the background.
  • Models leave when idle. A model unloads after its idle time, so the GPU drops back to rest.
  • Watts at the wall. CPU, GPU and the rest, kWh per day and month, and what the PC adds to your electricity bill at your tariff.
  • Cost per request. Tokens, tokens per second, joules and money for each request, session, model and repo.
06 · Safety

It runs commands for you, so it is locked down.

Treat Cerberus like an SSH login to your own account. The threat model says what it protects, from whom, and where it stops.

  • Private by default. It listens on 127.0.0.1. You add your LAN or tailnet address on purpose, and a token guards everything.
  • One token per device. Pair each phone or laptop with a QR code, revoke a lost one, rotate the admin token.
  • A sandbox for agents. Sessions can run inside bubblewrap, with a command policy for the built-in agent.
  • An audit log and a doctor. An audit log records who did what, and cerberus doctor checks the setup and prints the fix for each problem.
  • Tested route by route. A test walks all 116 routes and checks sign-in, the cross-site guard, what an agent's token may reach, and that every change is audited. Data files are private to your user.

07 · Install

Build it, answer six questions, start it.

Needs Go 1.26 or newer to build, plus git and bash for sessions. Optional: llama-server, LM Studio, Ollama, and nvidia-smi or the amdgpu driver for GPU readings.

  1. Get the source.
    $ git clone https://github.com/MiguelCarino/Cerberus && cd Cerberus
  2. Build. A static binary in dist/cerberus, no cgo.
    $ make build
  3. First run. It looks at the machine (engines, models, GPU, agents, Tailscale), asks up to six questions, writes the config and prints a sign-in link with a QR code. --yes takes the defaults.
    $ ./dist/cerberus init
  4. Keep it running. Installs the binary in ~/.local/bin and starts a systemd user service.
    $ ./dist/cerberus install-service
  5. Open it. Prints a sign-in link for every listen address. Open it on this machine, or pair a phone with cerberus pair --name phone.
    $ cerberus url

macOS builds and runs, agent sessions included. The service installer and the Linux-only extras (the bubblewrap sandbox, CPU power readings) are not there yet, so start it by hand or from your own launch agent.

  1. Get the source and build.
    $ git clone https://github.com/MiguelCarino/Cerberus && cd Cerberus $ make build
  2. First run, then start it.
    $ ./dist/cerberus init $ ./dist/cerberus serve

Windows builds and serves models and the gateway. Agent sessions need a terminal device (PTY) that Windows support does not have yet, and there is no service installer.

  1. Build (in PowerShell, with Go and git installed).
    > git clone https://github.com/MiguelCarino/Cerberus; cd Cerberus > $env:CGO_ENABLED="0"; go build -o dist\cerberus.exe .\cmd\cerberus
  2. First run, then start it.
    > .\dist\cerberus.exe init > .\dist\cerberus.exe serve
08 · Questions

Short answers.

Why one service instead of separate tools?

Running coding agents in their own git worktrees is a known idea. Cerberus puts it next to the rest: it is a background service you reach from any browser, your phone included; it hosts the models and one OpenAI-compatible gateway, so agents can run on a model your own machine serves; and it measures what each request costs in tokens, money and energy.

Can I use my LLM subscription?

Yes, but only through the vendor's official command-line tool, run as an agent session. Cerberus never proxies a consumer subscription. API keys are different: they go through the gateway, from the vault.

Do I need a particular vendor's software?

No. Everything works with no vendor CLI installed: the built-in agent uses whatever model the gateway serves, local or cloud. Other CLI agents and cloud providers are optional profiles you add.

Which systems does it run on?

Linux first. The code is pure Go with no cgo, so it builds for macOS and Windows today. macOS runs the service and agent sessions, without the Linux-only extras. Windows has no agent sessions yet. A desktop client comes later; until then any OpenAI-compatible chat app can use the gateway.

Do I need a GPU?

Not to start. Cerberus reads NVIDIA and AMD cards when they are there, and plans model loads around free VRAM. Without one, you can run small models on the CPU through your engine, or use cloud models through the gateway with your own keys.

Can I put it on the internet?

Please don't. Keep it on loopback, your LAN or your tailnet, use TLS for anything that is not loopback (for example tailscale cert), and pair each device instead of sharing the admin token. The threat model explains why.

Models
llama.cpp · LM Studio · Ollama
  • Supervises llama-server, lms and Ollama; vLLM is planned. It starts and stops them, it does not replace them.
  • On-demand loading with an idle timeout per engine, and a default model that default resolves to.
  • A resource guard and queue: sessions and loads wait when memory or VRAM is short.
  • Usage per request: time to first token, tokens per second, energy, and cost when you set prices.
  • cerberus top and the Monitor view show CPU, GPU, power and what is running.
README ↗
Gateway
OpenAI-compatible /v1
  • One base URL for editors, scripts and chat apps: http://127.0.0.1:7340/v1.
  • Routes by model ID: a local backend ID, or <provider>/<model> for any OpenAI-compatible cloud provider. A unique prefix or suffix also works.
  • Keys come from an environment variable or the vault, never from the request. Values are never printed.
  • Prices, budgets and subscription gauges, with alerts before a budget runs out.

Agents
worktrees · test gates · remote steering
  • Three places to work: a repo's detached worktree behind its checks, a folder of yours edited in place, or a scratch folder you save or discard later.
  • Steer from the browser: live terminal, quick keys, approvals, escalation to a stronger model, diff review, accept or discard.
  • Fleet tasks start one session per matching repo; agents can start and steer child sessions.
  • History with search and resume, voice tasks through local Whisper, and file drop into a session.
  • Notifications when a session finishes, waits or fails.
